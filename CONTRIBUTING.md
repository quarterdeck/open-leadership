# How to contribute

Open Leadership gets better when people who manage, teach and assess tell us what is wrong and
help to correct it. All contributions are welcome: a spelling correction, a better workplace
scenario, a new unit, an analysis of pilot data.

## Before you start

- Read the [manifesto](MANIFESTO.md) and the [governance](GOVERNANCE.md).
- For anything larger than a correction, open an issue first, so that nobody does work that
  cannot be accepted.

## Your contribution must be your own work

This is the most important rule.

- Write every sentence yourself. Do not copy, closely paraphrase or translate text from the unit
  specifications, handbooks, questionnaires, scoring keys or reports of any awarding body,
  professional body or test publisher.
- You can use public facts (levels, hours, credit values, titles) and openly licensed sources.
- If you use a source, add it to [SOURCES.md](SOURCES.md) with its link, the facts you took and
  its licence.
- Questionnaire items come only from the International Personality Item Pool or are new items
  that you wrote.
- If you used an AI tool, check the result against these rules. You are responsible for it.

When you open a pull request, you confirm that the contribution is your original work, or that
its source permits this use, and that you give it under the MIT licence.

## Writing standards

- British English. Plain, direct, short sentences.
- No em dashes. No filler words.
- Learning outcomes start with a measurable verb: analyse, apply, evaluate, plan.
- Each unit has a short, practical workplace scenario.
- No clinical or diagnostic language in the profiles.
- Never state or imply that Open Leadership is accredited, regulated or equivalent to another
  qualification.

## Files

- All documents are Markdown.
- Each file starts with the licence line:
  `<!-- SPDX-License-Identifier: MIT. Copyright (c) Quarterdeck. -->`
- One unit is one file in `framework/unit-bank/`. Keep the code and the size of an existing unit.
- If you change what a learner must do, increase the version number as the governance says.

## Report a problem

Open an issue. If you think that some content is too close to proprietary material, say which
passage and which source. We treat that as urgent.
